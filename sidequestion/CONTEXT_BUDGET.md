# 보조 질문의 긴 대화와 컨텍스트 예산

2026-09-11 수정. 원래 구현은 요청 JSON의 문자 수를 그대로 token으로 간주하고 메인 작업의 32K 출력 예약량을 상속했으므로, HTML·JS·도구 결과가 많으면 정상적인 보조 질문을 너무 일찍 거부했습니다.

## 오픈 소스 구현 대조

- [Grok CLI 보조 질문 컨텍스트](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자·어시스턴트 텍스트에서 조각을 추출하며, 문자 예산은 약 2000이고 항목마다 최대 400자를 가져옵니다. 이 경로에서는 연속된 보조 질문·답변 이력을 유지하지 않습니다.
- [Grok CLI 독립 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호. 모델이 지원하면 출력 상한은 2048 tokens이며 도구를 제공하지 않습니다.
- [Grok CLI 메인 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): token을 추정하고 최근 내용을 유지하며, 새 내용으로 이전 요약을 갱신하고 턴 경계에 걸친 잘림을 처리합니다.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력/버퍼 예약, 최근 내용과 누적 갱신 요약, 도구 없는 요약 요청. 이 구현의 기본 최근 내용 예산은 8000, 요약 출력 상한은 4096 tokens입니다.
- [OpenCode 상한 초과 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 어시스턴트 출력을 아직 시작하지 않았을 때만 상한 초과 복구를 시도하며, 복구 후 호출은 같은 복구 경로로 다시 들어가지 않습니다.

ARTEX는 독립 출력 예산, 최근 내용과 누적 갱신 요약, 제한적인 복구 방식을 참고합니다. norma v0.3.6의 구조화 메시지와 도구 쌍을 유지하며 Grok의 텍스트 발췌를 그대로 적용하지 않습니다. OpenCode의 메인 세션 압축 이벤트를 ARTEX 메인 transcript에 기록하지 않습니다.

## 요청 예산과 실행

- 메시지는 norma의 내용 블록별 UTF-8 바이트 추정 및 4/3 여유량을 그대로 사용하며, 시스템 프롬프트·도구 schema·메시지 포장 비용을 추가로 계산합니다. 추정치는 모델의 정확한 token 수가 아닙니다.
- 보조 질문 출력은 기본 최대 8192 tokens이며, 메인 설정에서 정한 출력 상한도 넘지 않습니다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 상한을 설정할 수 있으며, 제품 기본 모델이나 메인 작업 파라미터를 바꾸지 않습니다.
- 입력 예산은 컨텍스트 창에서 출력 상한과 안전 여유량을 뺀 값입니다. 창을 알 수 없으면 플랫폼 기본값 200K를 사용합니다. 안전 여유량은 창의 5%이며 최소 128, 최대 8192 tokens입니다.
- 성공한 질문·답변은 증가하는 순번으로 배치마다 최대 20그룹을 로드합니다. 원문은 최대 20그룹을 유지하며, token 예산은 입력 예산의 최대 1/4이고 16K도 넘지 않습니다.
- 초과한 질의응답은 누적 갱신 요약에 반영합니다. 요약에는 이력 출처와 컨텍스트 시각을 포함합니다. 이력의 assistant 답변은 새 도구 증거와 같지 않으며, 충돌 시 최신 메인 스냅샷을 우선 근거로 삼습니다.
- 메인 컨텍스트가 여전히 너무 길면 복사본의 오래된 메시지만 요약하며, 최근 내용은 최대 8K tokens를 유지합니다. 잘라내는 지점에서 도구 호출과 결과를 분리하지 않습니다. 너무 큰 단일 그룹은 전체를 요약에 넣습니다.
- 요약 입력은 실제 남은 창에 따라 UTF-8을 유지하며 나누고, 출력 상한은 2048 tokens입니다. 빈 요약·잘림·도구 호출·요약 예산 초과는 모두 캐시에 기록하지 않습니다. 단일 보조 질문은 최대 12회의 요약 호출을 수행하며 같은 120초 타임아웃을 적용합니다. 상한에 도달하면 명시적으로 실패하며 무한 반복하지 않습니다.
- 모델이 처음 컨텍스트 상한 초과를 반환했고 아직 텍스트나 도구 호출을 출력하지 않았으면, 추가 축소 후 최대 한 번 재시도합니다. 추정 크기가 줄지 않으면 즉시 복구를 중단합니다. 다른 모델 오류와 일부 스트리밍 출력은 이 복구를 트리거하지 않습니다.
- 요약·실패한 시도·취소 시 사용량을 포함해 얻은 모든 사용량을 같은 보조 질문 요청에 누적합니다. Provider가 사용량을 반환하지 않으면 여전히 영만 기록할 수 있으며, 추정치를 실제 사용량으로 가장해서는 안 됩니다.

## 영구 저장과 화면

`side_question_sessions.memory`는 이전 질문·답변 요약, 포함한 ordinal 및 스냅샷 식별 정보에 따라 캐시한 메인 컨텍스트 요약을 저장합니다. `side_question_requests.context_info`는 준비 단계·실제 재생 그룹 수·요약 사용 여부·예산 추정을 저장합니다.

요약은 원래 요청이 아직 실행 중이고 정리 버전이 일치할 때만 저장합니다. 비우기는 캐시도 함께 지우며, 늦은 쓰기가 정리된 데이터를 복원하지 않습니다. 새 스냅샷은 이전 스냅샷 요약을 재사용하지 않습니다. 요약 필드는 v3 작업 아카이브에 저장하며, 기존 v3에 없는 필드를 복구할 때는 빈 객체를 넣고 v1/v2 호환을 유지합니다.

POST는 먼저 요청을 수락해 반환하고 준비와 압축은 백그라운드에서 실행하며 요청 수락 잠금이나 데이터베이스 트랜잭션을 유지하지 않습니다. SSE/이력에는 준비, 질의응답 정리, 복사본 압축, 답변 단계가 표시됩니다. 압축 실패는 해당 보조 질문 요청의 실패 종료 상태로 저장합니다. 프런트엔드는 오류를 유지하고 이번에 실패한 질문의 초안을 복구하며, 입력란을 가리는 플로팅 알림을 사용하지 않습니다. 이력 폴링은 더 이상 제출 오류를 지우지 않습니다.
