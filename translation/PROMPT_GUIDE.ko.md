# ARTEX 한국어화 가이드 — 백엔드·프롬프트·인프라 (Stage 2·3+)

UI 1단계(프런트엔드 문자열, `web/`) 완료 후 **저장소 나머지 전체**를 한국어화하기 위한 작업 기준이다.
최종 목표는 **ARTEX 저장소 대부분의 중국어 한글화**이며, 빠지는 파일이 없도록 **§1 커버리지 맵**이 모든 영역을 단위로 배정한다.
용어·표기는 [`GLOSSARY.ko.md`](./GLOSSARY.ko.md)를 그대로 따른다.

작업은 성격에 따라 **3개 트랙**으로 나뉜다:
- **트랙 A · 프롬프트(U1~U9·U15)** — 에이전트가 읽는 프롬프트. **번역이 모델 동작을 바꿀 수 있어** 검증 비중이 가장 크다.
- **트랙 B · 백엔드 Go 비프롬프트(U10~U13)** — API 에러·DTO 주석·DB·알림 템플릿·로그. 대체로 UI 수준 난이도.
- **트랙 C · 스크립트·인프라·설정(U14)** — `*.sh`·Dockerfile·compose·CI·설정 예시. CLI 출력·주석.

> **규칙 적용은 "트랙"이 아니라 "그 문자열을 누가 읽느냐(실제 소비자)"로 판단한다.** 모델이 읽는 문자열(프롬프트·도구 설명·스키마 설명·모델에게 보내는 안내문/요청 메시지)에는 **소속 트랙과 무관하게 §2 전체(지시 강도·출력 범위 포함)**를 적용한다. 사람·로그·UI만 읽는 문자열에는 DNT·포맷 지정자·전각→반각·조사 규칙을 적용한다. **트랙 B(server/·db/ 등)에도 모델이 읽는 문자열이 섞여 있다** — 예: `server/chat_mentions.go`(참조 기록은 지시·권한이 아니며 기존 규칙을 덮어쓰면 안 된다는 안내), `server/finding_retests.go`(재검증 도구 설명·스키마 설명), `db/finding_retests.go`(재검증 세션 요청 메시지). 사용자 표시 문구와 모델용 문자열이 **섞인 파일은 둘을 구분해 검토·기록**한다. (파일 소유권은 그대로 — U11·U12 담당자가 모델용 부분에 프롬프트 규칙을 적용.)

## 0. 범위와 전제

- **Stage 2(출력 한국어화)**: 프롬프트 안의 "중국어로 답하라"류 지시를 "한국어로 답하라"로. 지시문이 프롬프트 본문에 박혀 있어 Stage 3와 **같은 파일에서 함께** 처리한다.
- **Stage 3(프롬프트 본문 번역)**: 프롬프트의 중국어 설명을 한국어로.
- **중국어 문자열이 코드의 비교·파싱에 쓰이는 계약이 실재한다.** 기존에 확인한 소스에서는 `intercept/prompt.go`의 프롬프트 형식·출력 예시와 같은 파일의 판정 파서(`HasPrefix`/`strings.Cut`)가 중국어 앵커(`实际操作：`·`；成功后的后果：`·`；命中规则：`)를 공유한다. 모델 출력이 앵커와 다르면 파서가 유효 결과로 받지 못한다. 번역 전 **용어집 §5.7과 최신 브랜치의 생성부·소비부를 함께 확인하고 계약 문자열을 보존**한다. 이전 "직접 매칭 0건" 서술은 grep 정규식이 `함수(인자, "..."` 형태를 놓친 오판이었다는 팀원 검토를 반영하여 폐기한다.
- **계약을 보존하더라도** 표현·지시 강도·출력 형식 변경이 모델의 **도구 선택·구조화 출력**을 바꿀 수 있다. 그래서 **정적 검토 상태와 실행 검증 상태를 구분해 기록**하고(§3·§4), "독립 번역 안전"이 아니라 "단위별 동작 검증 필수"로 다룬다.
- **확인 전 원칙**: 최신 브랜치에서 계약의 위치·유지 여부를 다시 확인하되, **확인 전까지는 기존 계약을 번역 가능한 것으로 처리하지 않는다.**

## 1. 작업 단위와 커버리지 맵 (U1 → U15)

한 번에 **한 단위씩** 번역 → 검토 → 검증 → 커밋한다. **각 단위는 그 구현을 검증하는 관련 테스트까지 함께 확인한다** — 같은 이름의 `*_test.go`뿐 아니라 이름이 다른 테스트(예: `insert_assets_test.go`·`tools_overview_test.go`·`provider_capture_test.go`)도 포함. **표시 문자열 번역에 필요한 기댓값만** 바꾸고, 계약·길이·위치·인코딩 검증용 데이터는 중국어라도 일괄 번역하지 말고 별도 판단한다. 여러 단위가 공유하는 테스트는 편집 담당자를 정한다. 트랙 A는 **U1을 먼저** 끝내 기준을 깐 뒤 진행.

**사람별 담당**(최신 분담표):

| 담당 | 단위 |
| --- | --- |
| 사람1 | U2 · U3 · U4 · U9 |
| 사람2 | U5 · U6 · U7 · U8 |
| 별도 지정 | U1(정적 검토 완료 보고·컨텍스트 라벨 계약 검토 보류·실행 미검증) · U10~U15 (담당 미정/보류) |

팀원의 기존 U1 "완료" 보고는 `PROMPT_PROGRESS.ko.md` U1의 기존 보고 기록으로 보존한다. 현재 상태는 위 표의 보류·미검증 구분을 따르며, 새 계약 확인·실행 검증 근거 없이 최종 완료로 올리지 않는다.

**규칙 우선순위**: ① 사용자의 작업 지시·실행 제한이 최우선 → ② 용어·DNT는 `GLOSSARY.ko.md` → ③ 파일 소유권은 최신 분담표. 문서 간 충돌은 임의 해석하지 말고 **보고**한다.

### 트랙 A · 프롬프트 (agent/intercept/report/sidequestion)

**U1 · 공용 기반 ⭐가장 먼저** — `agent/promptcatalog.go`·`prompt.go`·`assembly.go`·`chat.go`
모든 에이전트가 공유하는 프롬프트 토대. `promptcatalog.go`에 공통 시스템 프롬프트 상수(`DefaultAssistantPrompt` 등), `prompt.go`의 `renderSystem`이 `{{.Var}}` 템플릿 렌더링, `assembly.go`가 조립, `chat.go`가 소비. **여기서 출력-언어 지시의 번역 어휘(§2.5)와 공통 용어 기준을 맞춰** U2~U9가 참조(강제 통일이 아니라 일관성 기준점).

**U2 · 플래너 계열** — `agent/planner.go`·`goals.go`·`constraints.go`
계획 수립 루프(의도 생성, 목표/제약 관리). 현재 상태는 **번역·정적 검토 완료 보고 / 관련 테스트 확인 보류 / 실행 미검증**이며, 팀원의 작업·검증 기록과 확인 보류 항목은 `PROMPT_PROGRESS.ko.md` U2에 함께 보존한다.

**U3 · 워커 실행** — `agent/worker.go`·`wrapup.go`·`compaction.go`·`noa.go`·`capture.go`·`coldgraph.go`
워커 1회 실행(run) 수명주기 — 실행 프롬프트 + 마무리 + 컨텍스트 압축 + 캡처/콜드그래프.

**U4 · 메인/리테스트/발견** — `agent/mainagent.go`·`retester.go`·`finding_workflow.go`·`finding_recorder.go`
대화형 메인 에이전트 + 재검증 + 발견 기록.

**U5 · 도구 설명(분량 최대)** — `agent/tools.go`·`tools_insert.go`·`toolcatalog.go`·`tools_digest.go`
에이전트가 읽는 도구 설명·카탈로그. DNT 최다(도구명·파라미터·스키마 키). 크면 `tools.go`/`tools_insert.go`로 2분할.

**U6 · 상태/사유 문자열** — `agent/terminalreason.go`·`cancelcause.go`·`provider.go`
종료/취소 사유 코드→설명 맵(표시용) + provider 주석/에러. 사유 **코드 키** DNT, 설명만 번역.

**U7 · 인터셉트** — `intercept/` **패키지 전체**(prompt.go·review_context.go·intercept.go·trace.go 등)
모델 대체 승인 심판 프롬프트 + 인터셉트 로직 주석·메시지. ⚠️ **판정 사유 계약 앵커**(`实际操作：`·`；成功后的后果：`·`；命中规则：`, 전각 콜론/세미콜론 포함)와 `[模型]` 접두사는 **DNT** — 기존 확인 소스의 생성부(프롬프트 형식·예시)와 소비부 파서는 모두 `intercept/prompt.go`에 있으며, 같은 문자열을 써야 한다. 최신 위치를 대조하고 앵커 사이 자유 서술만 번역한다(§2.2). `[模型]`는 프런트(approval-records.tsx)도 매칭하므로 보존한다.

**U8 · 리포트** — `report/` **패키지 전체**(findings.go·report.go)
취약점 리포트 생성 프롬프트 + 로직.

**U9 · 사이드 질문** — `sidequestion/` **패키지 전체**(context.go·request.go·service.go 등)
`/btw` 보조 질문 프롬프트 + 오케스트레이션 로직. **(작업 라벨 생성부·참조부 정적 확인)** U1 `ReporterDefaultPrompt`(`agent/promptcatalog.go:80`)의 실제 참조는 `"작업 #<id>"`이며, 생성부 `server/conversations.go:710,712`의 `taskContextHeader`는 `"[작업 #%d %s (목표: %s)]"` 또는 `"[작업 #%d %s]"`를 생성하여 `작업 #` 표기가 일치한다. PROGRESS의 “라벨 계약 해소 (U1↔U11 교차, 2026-10-05)” 기록을 참조한다. 이 확인은 해당 라벨에 한정하며 다른 U1 보류를 해소한 것으로 확대하지 않는다. 이번 재대조는 정적 검토이고 실행 검증은 사용자 요청으로 미실행이다.

**U15 · 내장 스킬 번들** — `skills/` (`api-recon/SKILL.md`·`reference.md`·`scopesentry/SKILL.md` + `scripts/*`)
에이전트가 로드하는 **스킬 지시문**(SKILL.md)·참고 문서·헬퍼 스크립트. SKILL.md 본문은 프롬프트성(트랙 A 규칙 적용)이나, **YAML 프런트매터 키·스크립트 코드·명령/경로·셀렉터는 DNT**. 스크립트는 주석만 번역.

| `skills/` | U15 |
| `README.md` `CHANGELOG.md` `docs/` `translation/` `mock/data.ts·handler.ts` | 결정/보류/DNT (위 참고) |

팀원의 기존 UI "완료(UI 1단계), 잔여는 DNT" 보고는 이력으로 보존한다. 현재 UI 상태는 최신 통합 점검 기록을 참조하며, 잔여 전체를 DNT로 단정하지 않고 위 분류를 적용한다. 팀원이 잔여 agent 파일의 CJK 0을 보고한 사실도 보존하되, 전체 문맥 검토 완료나 담당 배정을 뜻하지 않는다.

> 신규 파일이 생기면 위 표에 먼저 배정하고 작업한다. 단위 착수 전 `git ls-files` 로 담당 영역의 **미할당/신규 중국어 파일**을 재확인(§6 NUL 주의). 중국어 파일명(예: `docs/漏洞流量证据.md`)은 `git ls-files -z` 로 널 구분해 스캔해야 누락되지 않는다.

## 2. 공통 규칙 (이것만 지키면 안 깨진다)

### 2.1 템플릿 문법 **전체** 보존
Go `text/template`과 `fmt`를 쓴다. **치환자뿐 아니라 제어 구문·포맷 지정자 전부 그대로** 둔다.
- 변수: `{{.Goal}}` `{{.Now}}` `{{.DataDir}}` …
- 제어: `{{if .X}}` `{{else}}` `{{range .Items}}` `{{end}}`
- 공백 제거: `{{- ... -}}`
- 포맷 지정자: `%s` `%d` `%v` … — **개수·순서 그대로**. 한국어 어순상 바꾸고 싶어도 `Sprintf` 인자에 위치로 매핑되므로 **재배치 금지**.

```
원문 : fmt.Sprintf("已完成 %d 个目标，还剩 %d 个", done, left)
한국어: fmt.Sprintf("목표 %d개 완료, %d개 남음", done, left)   // %d 2개·순서 동일
```

### 2.2 DNT — 원문 유지 (프롬프트에서 확대 적용)
다음은 **번역하면 에이전트가 깨진다**. 반드시 원문 유지:
- 도구명: `traffic_search` `update_finding_report` `get_worker_trace` …
- 파라미터·옵션명: `body_contains` `host` `limit` `id` …
- JSON 출력 키·필드명: `summary` `state` `vulnclass` …
- enum 값: `exploring` `blocked` `exhausted` `open` `pause` …
- 멘션 토큰 종류명: `@[漏洞#id]`의 `漏洞`·`资产`·`企业` 등 (§5.7 값 계약)
- reason/cause **코드 키**: `cause("paused_by_user", …)`의 `"paused_by_user"` — **설명 문자열만 번역**
- **인터셉트 판정 사유 계약 앵커**: `实际操作：` · `；成功后的后果：` · `；命中规则：` 는 **앵커 그대로 보존**하며, 앵커 안의 **전각 콜론 `：`·세미콜론 `；`도 변경 금지**. 기존 확인 소스에서는 `intercept/prompt.go` 안의 프롬프트 형식 설명·출력 예시와 판정 파서가 **같은 문자열**을 사용한다. 최신 위치를 확인하되 각 구간 사이의 **자유 서술 내용만** 번역한다. `[模型]` 접두사와 그 밖의 값 계약은 §5.7(GLOSSARY)을 따른다. ※ 앵커를 한국어로 바꾸며 파서까지 고치는 일은 이번 번역 범위 밖.
- 경로·명령·env·URL·`{{.Var}}`·백틱 코드블록 내부 식별자

> 판단 기준: *"모델이 이 글자 그대로 출력해야 하거나, 코드/다른 시스템이 이 글자로 식별하는가?"* → 그렇다면 DNT.

### 2.3 지시 강도 보존
프롬프트에선 어감이 곧 동작이다. **약화도 강화도 금지.**
- `必须/一定` → **반드시** (≠ ~하면 좋다)
- `尽量/建议` → **가능하면 / 권장** (≠ 반드시)
- `禁止/不要` → **금지 / ~하지 마라** (≠ 지양)
- `先…再…` 같은 **실행 순서**, `除非/如果` 같은 **조건·예외**는 그대로 보존.

### 2.4 한국어 출력 범위 — 자유 서술값과 계약값 구분
- **자연어 설명·지시 → 한국어.**
- **JSON 키 · enum · 도구명 · 필수 리터럴 → 원문.**
- **JSON "값"은 둘로 나눠 판단한다**:
  - **자유 서술 값**(모델이 자연어로 채우는 설명류, 예 `summary`) → 한국어.
  - **계약·enum·매칭·식별 값**(코드가 비교/분기하거나 다른 시스템이 식별하는 값, 예 상태 enum, 고정 분류, 앵커가 걸린 필드) → **원문 유지**. 특정 필드가 둘 중 뭔지 불확실하면 **생성부·소비부를 확인하기 전까지 원문 유지**.
- **예시 출력(JSON 샘플, 도구 호출 예)도 위 원칙에 맞춘다** — 키·구조·계약값은 원문, 자유 서술 값만 한국어.

```
원문 예시 출력:
  {"summary": "对 example.com 做目录爆破", "vulnclass": "信息泄露"}
한국어화:
  {"summary": "example.com 디렉터리 무차별 대입", "vulnclass": "信息泄露"}
  // 키(summary/vulnclass)=원문. summary=자유 서술→한국어.
  // vulnclass 값은 분류·필터 매칭에 쓰일 수 있어, 계약 여부 확인 전엔 원문 유지(확인 후 자유값이면 번역).
```

### 2.5 출력 언어 지시 — 원문 조건·범위 보존 (강제 통일 금지)
`请用简洁、准确的中文回答` / `用人话简洁回复` / `全程中文` / `使用简洁中文答复` 류는 **언어 부분만** 한국어로 바꾼다("중국어로"→"한국어로"). **모든 지시를 하나의 표준 문구로 치환하지 말 것** — 원문에 없던 요구(간결·정확 등)를 임의로 추가하거나 적용 범위를 바꾸면 안 된다. 각 지시의 **조건·수식어·적용 범위를 원문 그대로** 둔 채 언어만 교체한다(예: `全程中文`="전 과정 한국어", `用人话简洁回复`="쉬운 말로 간결하게 답하라" — 원문 어감 유지). U1은 "표준 문구 **강제 통일**"이 아니라 반복되는 출력-언어 지시의 **번역 어휘를 일관**되게 맞추는 기준점일 뿐이다.
※ 주의: `worker.go`의 "支持子串和中文(검색)" 처럼 **출력 언어가 아닌 기능 설명**의 "中文"은 출력지시가 아니다 — 문맥 보고 그냥 번역.

### 2.6 전각→반각·조사
GLOSSARY §6 동일. **산문의** `，：；（）「」、。`→반각, 변수 뒤 조사 금지(`{{.X}}` 뒤 은/는/을/를 금지, `을(를)`·`(으)로` 병기).
- **`、` → `·` 또는 `, ` 변환은 산문에만 적용한다.** 계약 앵커·정규식·파서 구분자의 전각 부호는 보존한다.
- **코드 구분자는 별도 제한**: `strings.Join(…, "、")` 등 코드 안 구분자는 순수 표시용으로 보이더라도 **용어집 §7.2에 명시된 허용 위치에서만** 변경한다. 그 밖의 위치는 보존하고, 변경 필요성이 있으면 검토 대상으로 보고한다. `intercept` 계약 앵커의 전각 `：`·`；`도 변경하지 않는다.

## 3. 검증 (단위 완료 기준)

| 단계 | 내용 | 필수 |
| --- | --- | --- |
| 빌드 | `go build ./...` 통과 | ✅ |
| 테스트 | 해당 단위 관련 `go test ./<pkg>/...` 통과(기댓값이 중국어면 동시 조정 or 사유 기록) | ✅ |
| 템플릿 렌더 | 프롬프트가 렌더 오류 없이 생성되는지(치환자·제어구문 보존 확인) | ✅ |
| 1 run 스모크 | 해당 단위 에이전트를 실제 1회 실행해 **도구 호출·구조화 출력**이 정상인지 | 권장(최소선) |

- 1 run은 **최소 확인**이다. 실행 못 한 부분은 **"미검증"** 으로 기록에 남긴다.
- 기호 parity(따옴표·백틱·`{{`·`}}` 개수)와 중국어 잔여(NUL 포함 파일은 `tr -d '\000'` 후) 스캔은 UI와 동일하게.
- **번역 대상 중국어 누락 0 — DNT 잔여는 별도 보고**: 한자와 전각 문장부호를 다시 검색하고, 잔여를 DNT·원문 예시·용어 보류·계약 검토 보류·후속 단계 보류로 구분한다. 보류는 번역 완료나 DNT로 처리하지 않는다. 계약 보존에 필요한 중국어·전각 부호의 잔여는 정상이며, 전체 잔여 0건을 일괄 요구하지 않는다.
- **번역 완료 ≠ 실행 검증 완료 (반드시 분리 기록)**: 번역 대상 누락·잔여 분류·코드/계약 보존·기호 비교는 정적 검토 항목이다. 기호 개수 비교는 보조 확인이며 구문·렌더·동작 검증을 대신하지 않는다. `go build`/`go test`/실제 템플릿 렌더/1 run은 실행 검증이다. 실행 환경이 없거나 사용자가 실행을 제한하면 각 실행 항목은 **미검증과 미실행 사유**를 기록하고, **단위를 최종 완료(done)로 단정하지 않는다**. 번역·정적 검토·보류 상태를 별도로 기록한다.
- **사람2의 현재 실행 제한**: 저장소·의존성 코드·Git 훅을 실행하지 않는다. 설치·빌드·타입 검사·lint·테스트·실제 템플릿 렌더·앱·화면·스모크·`gofmt`는 **사용자 요청으로 미실행**으로 기록한다. 실행 환경이 갖춰져 있어도 별도 허용 없이는 수행하지 않는다. 정적 Git 검토는 `core.fsmonitor=false`·`--no-ext-diff`·`--no-textconv`를 사용한다. 다른 담당자는 자신에게 허용된 환경·실행 범위에서 검증하고 실제 결과를 기록한다. 이 문서의 명령 예시는 실행 허가가 아니다.

## 5. 커밋·동기화 절차
- **메시지**: 한국어, 한자 금지, 타입 `translation(prompt):`(코드)·`translation(glossary):`(용어집)·`translation(docs):`(문서). Claude 트레일러 금지.
- **커밋 전**: 단위의 정적 검토·보류·실행 검증 상태(§3)를 보고하고 사용자 검토를 받는다. 실행 미검증 상태의 번역 커밋이 최종 동작 검증 완료를 뜻하지는 않는다.
- **Codex 종료 지점**: 별도 지시 없이 `git add`·commit·push·다음 단위 진행을 하지 않는다. 사람2는 사용자 검토 후 직접 커밋·push한다.
- **푸시 전 동기화**(순서 고정):
  1. 현재 브랜치·HEAD·Git status·staged/unstaged 변경과 진행 중인 병합을 확인한다. 기존 로컬 변경·미추적 파일은 필요한 백업 후 보존한다.
  2. `git fetch origin` 후 로컬·원격 커밋과 변경 파일을 비교한다.
  3. 원격 신규 커밋이 있으면 `git pull`·rebase 대신 **`git merge --no-commit --no-ff origin/work/ko-translation`**으로 병합 커밋 직전까지 진행한다. 훅·fsmonitor는 비활성화한다.
  4. 충돌·로컬 덮어쓰기 거절이 나오면 보고하고 멈춘다. 기존 변경을 임의로 삭제·복원·stash하지 않는다. 확정 용어·계약 판단이 필요한 충돌도 사용자에게 확인한다.
  5. 병합 결과·전체 staged diff·기존 변경 보존을 검토한 뒤 사용자가 병합 커밋·push한다. 관계없는 로컬 변경은 포함하지 않고 강제 push하지 않는다.

정적 확인·동기화 명령 예시(현재 상태 확인 후 필요한 명령만 실행):

```bash
git -c core.fsmonitor=false status --short
git -c core.fsmonitor=false -c core.hooksPath=/dev/null fetch origin
git -c core.fsmonitor=false log --oneline --left-right HEAD...origin/work/ko-translation
git -c core.fsmonitor=false -c core.hooksPath=/dev/null \
  merge --no-commit --no-ff origin/work/ko-translation
git --no-pager -c core.fsmonitor=false diff \
  --cached --no-ext-diff --no-textconv
```

위 예시는 자동으로 전부 실행하는 스크립트가 아니다. 충돌·거절·기존 병합 상태가 있으면 후속 작업을 중단한다.
- 자격 증명이 없는 환경에서는 push가 실패하니, 이 경우 **명령만 사용자에게 전달**하고 임의로 우회하지 않는다.

## 6. NUL 바이트 주의
`exploration-graph.tsx`처럼 소스에 기존 NUL이 있으면 검색 도구가 바이너리로 보고 중국어를 놓칠 수 있다. 검수는 **텍스트 모드로 한자와 전각 문장부호를 함께 검색**한다. 예: `rg -n --text '[\p{Han}，：；、「」【】（）《》．。]' '<대상 파일>'`. `tr -d '\000'`을 쓰는 경우에도 **스캔용 표준 출력에서만** NUL을 제외하고, 원본이나 수정 파일에 덮어쓰지 않는다. 기존 NUL의 용도를 임의로 판단하지 말고 **원본 바이트를 보존**한다.
