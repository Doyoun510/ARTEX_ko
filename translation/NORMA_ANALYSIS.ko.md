# **norma 분석**

대상: `Autumn-27/norma` (Go, ARTEX가 씀). 한 줄: "LLM을 자율 에이전트로 만들어주는 엔진". ARTEX의 진짜 두뇌.

---

## **핵심 요약**

1. norma = 범용 엔진. 코딩 로봇이든 보안 로봇이든 다 만들 수 있는 **빈 뼈대**
2. ARTEX에서 "잘 만들었다" 한 것 대부분(루프, 도구 관리, 권한 체크, 대화 압축, 서브에이전트, 스킬, MCP)이 사실 전부 여기 norma에 있었음. ARTEX는 이 엔진 위에 "침투테스트"라는 껍데기만 씌운 것
3. → 우리 프로젝트의 핵심 결정도 결국 "이런 엔진을 어떻게 마련하냐"

특이점!!! 남의 라이브러리를 거의 안 가져다 씀. 심지어 LLM이랑 통신하는 것까지 직접 다 짰음 (보통은 공식 SDK 쓰는데)

## **전체 구조**

- `agentcore` - 입구. 사용하는 쪽은 여기만 알면 됨. "세션" 하나 만들면 다 돌아감
- `harness` - 실제 루프(심장). 모델한테 말 걸고, 도구 실행 순서 정하고, 언제 멈출지 판단
- `tool` - 도구가 뭔지 정하는 규격 + 기본 도구들(파일 읽기/쓰기, 명령 실행, 검색)
- `permission` - 안전 담당. "이 도구 써도 되나?"를 허용/거부/물어보기로 판정
- `llm` - 모델이랑 통신하는 부분
- `compaction` - 대화가 너무 길어지면 요약해서 줄이기
- `hook` - 중간에 끼어들 수 있는 지점들
- `subagent`/`coordinator` - 자식 로봇한테 일 떼주기
- `skill`/`memory`/`mcp`/`plan`/`transcript` - 설명서(스킬), 기억, 외부도구 연결, 계획모드, 대화 저장

## **1. 설계에서 중요한 생각**

- 명령(프롬프트)은 쓰는 쪽이 채운다 - norma 자체엔 "너는 뭐 하는 로봇이다" 같은 설명이 하나도 없음. 완전 백지. 그걸 ARTEX가 다 채움 → 그래서 아무 용도로나 쓸 수 있음
- 도구는 기본값이 "잠겨있음" - 새 도구 만들면 기본값이 "위험할 수 있음(승인 필요)". 안전하다고 도장 찍은 것만 풀어줌 → 실수로 위험한 도구가 막 돌아가는 걸 방지
- 모델 바꿔도 구조는 그대로 - 안에서 형식을 하나로 통일해놔서, GPT를 쓰든 클로드를 쓰든 윗부분 코드는 안 바뀜

## **2. 루프 (제일 중요)**

한 바퀴 도는 과정:

1. 대화가 너무 길면 먼저 줄이고 → 모델한테 "지금까지 대화 + 쓸 수 있는 도구 목록" 보냄
2. 모델 답을 받으면서 "이 도구 써줘"라고 한 걸 모음
3. 그 도구들 실행 → 결과를 대화에 붙임. **모든 도구 요청엔 반드시 결과를 짝지어줌**(거부되거나 멈춰도 "거부됨"이라도 넣음 → 짝이 안 맞으면 모델이 헷갈려함)
4. 다시 1번으로. 모델이 더 이상 도구 안 쓰고 그냥 대답만 하면 그 바퀴에서 끝

끝나는 이유를 꼼꼼하게 구분함: 정상 종료 / 횟수 다 씀 / 시간 다 씀 / 대화가 너무 길어짐(→ 압축하고 재시도) / 모델 에러 / 훅이 종료를 막음

좋은점: 횟수나 시간이 다 떨어져도 그냥 뚝 끊지 않음. "곧 끝나니 지금까지 한 거 정리하고 한 줄 요약 남겨"라고 시키고 몇 턴 더 돌림. 이때 위험한 도구는 숨김 → ARTEX worker가 시간 떨어질 때 발견한 걸 안 버리고 저장하던 게 사실 이 기능

## **3. 도구 실행 순서**

- 그냥 보기만 하는 도구들(파일 읽기 등)은 **여러 개 동시에** 돌림 = 같이 해도 안 위험하니까
- 뭔가 바꾸는 도구(쓰기/실행)는 **혼자만** 돌림 → 돌 동안 나머지는 대기. 순서도 지킴
- 모든 도구 출력에 **최대 크기 제한** - 어떤 도구든 결과가 너무 크면 잘라내거나 파일로 빼냄 → 결과가 왕창 쏟아져서 대화가 터지는 사고를 한 군데서 막음

## **4. 도구 시스템**

도구 하나 = 이름 + 설명 + 입력 양식 + 안전 표시(보기만 하나/바꾸나) + 권한 자가점검 + 실제 동작. 만들 때 `Build`를 통하면 안전 기본값이 자동으로 채워짐

기본 도구: 파일(읽기/쓰기/편집), 명령 실행(Bash), 검색, (옵션)웹 가져오기·검색, 할 일 목록, 사용자한테 질문, 백그라운드 작업, 대화형 셸(콘솔)

대기중인 도구들 - 도구는 있는데 설명을 모델한테 안 보여줘서 토큰(글자 수) 아끼고, 필요할 때만 찾아 쓰게 함 → ARTEX가 MCP 도구를 평소엔 숨겨두던 게 이 원리

## **5. 권한 (안전 판정)**

도구 쓸 때마다 4단계로 "되나 안 되나" 판정.

1. 금지 목록에 걸리면 → 바로 거부 (어떤 설정이든 이게 1순위)
2. 설정 확인 - 다 허용 모드면 통과, 둘러보기만 모드면 읽기 도구만 통과
3. 허용 목록·읽기 도구면 → 통과
4. 안 걸러진 건 → 사람한테 물어봄

모드 6개(얼마나 빡빡하게 물어볼지): 기본 / 편집 자동허용 / 다 허용 / 둘러보기만 / 절대 안 물어봄 / 자동

좋은점: ARTEX는 norma 권한을 "다 허용"으로 열어두고, 대신 자기만의 승인 게이트를 위에 따로 얹음 → norma 권한 = SDK가 주는 기본 안전망, ARTEX 게이트 = 침투테스트용 세밀 정책. **우리 프로젝트도 이 두 층으로 나누면 깔끔할 것 같음**

## **6. 훅**

에이전트가 도는 중간중간 끼어들 수 있는 지점이 8개(도구 쓰기 전/후, 세션 시작/끝, 종료할 때 등). 여기서 도구 실행을 막거나, 입력을 바꾸거나, 종료를 막을 수 있음 → ARTEX 승인 게이트가 바로 "도구 쓰기 전" 지점에 물려서 동작함

## **7. 대화 압축**

오래 돌리면 대화가 계속 길어지니까 줄여야 함. 세 방식 다 원본은 안 버림:

- 오래된 도구 결과 본문만 지우기 (필요하면 다시 읽음)
- 임계치 넘으면 앞쪽 대화를 요약으로 접기 (원본은 두고 모델엔 요약만 보냄)
- 대화가 터지는 에러가 실제로 나면 → 강제로 요약하고 재시도

좋은점: 압축해도 **스킬(설명서)은 원문 그대로 다시 넣어줌** → 요약하다가 "이 작업은 이렇게 해라"

## **8. 서브에이전트 / 코디네이터**

- 서브에이전트 - 자식 로봇한테 일을 떼줌. 같은 엔진을 쓰되 자기 명령·도구·권한으로 **따로** 돎. 무한 반복 막는 깊이 제한(기본 3) 있음 → 자식이 하는 긴 작업이 부모 대화를 안 더럽힘
- 코디네이터 - 그 위. 대장이 일을 쪼개 여러 일꾼한테 나눔 (LLM이 알아서 / 코드로 병렬로)

참고: ARTEX의 기획자/실행자 분업은 이걸 그대로 쓴 게 아니라, ARTEX가 자기 방식으로 비슷하게 직접 만든 것

## **9. 스킬 / 기억 / MCP / 플랜**

- 스킬 - "이 작업은 이렇게 해라" 설명서(`SKILL.md`). 필요할 때 불러오고, 압축돼도 안 날아감 → ARTEX 스킬 시스템이 이거
- 기억 - 장기 기억. 파일 하나당 사실 하나로 저장 (ARTEX는 안 쓴 듯)
- MCP - 외부 도구를 붙이는 표준 방식. ARTEX는 여기에 HTTP 연결을 추가로 더 붙임
- 플랜 모드 - 먼저 둘러보기만 하며 계획 세우고 → 승인나면 그때 실제로 손댐

## **10. 모델 통신 / 대화 저장**

- 모델 통신 - GPT 형식·클로드 형식 둘 다 되고 안에선 하나로 통일. 통신을 바닥부터 직접 짬(남의 라이브러리 안 쓰려고)
- 대화 저장 - 대화를 파일로 한 줄씩 저장 → 나중에 이어서 할 수 있음. ARTEX worker가 멈췄다 재개하던 게 이 덕분

## **11. 우리팀 시사점**

ARTEX만 봤을 땐 "이걸 어떻게 다 만들었지" 싶었는데 norma 보니 이해 → **범용 엔진(norma) + 그 위에 침투테스트 로직(ARTEX)** 2층 구조.

선택지 3개:

- 기성 프레임워크(LangGraph 등) - 빨리 시작. 근데 ARTEX급 세밀 제어를 하려면 결국 많이 손봐야 함
- norma처럼 직접 만들기 - 제어는 완벽하나 품이 많이 듦(루프+도구+권한+압축만 1만 줄 넘음) → 이건 지금 불가능
- 파이썬으로 설계만 참고해서 필요한 만큼만 만들기 - 현실적으로 이게 절충안일 듯

어떤 길이든 챙길 설계

- 도구는 기본을 "잠금"으로 (안전부터)
- 모든 도구 출력에 최대 크기 제한 (대화 터짐 방지)
- 도구 요청엔 반드시 결과 짝지어주기 (거부·멈춤이어도)
- 시간 떨어지면 바로 끊지 말고 "수습" 한 바퀴 (발견 안 버리게)
- 대화 압축은 원본 안 버리고, 설명서는 다시 넣어주기
