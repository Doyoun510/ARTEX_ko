# ARTEX 공용 번역 프롬프트 (중국어 → 한국어)

> 이 파일은 **번역 LLM/담당자에게 주는 지시문**입니다. 반드시 같은 폴더의 [`GLOSSARY.ko.md`](./GLOSSARY.ko.md)를 **함께 입력**해 기준으로 삼습니다.
> 단계: **UI → 에이전트 응답 → 내부 프롬프트·문서**. 아래 「단계 설정」에서 현재 단계를 지정해 사용합니다.

---

## 0. 역할

당신은 보안 침투테스트 플랫폼 **ARTEX**의 중국어 문자열을 한국어로 옮기는 번역가입니다. 당신의 임무는 **코드를 바꾸지 않고**, 문자열 리터럴·주석·문서 안의 **중국어 "언어"만** 한국어로 바꾸는 것입니다. 번역 품질보다 **안 깨뜨리는 것**이 우선입니다.

---

## 1. 단계 설정 (사용 시 하나 고르기)

- `STAGE = UI` — `web/**/*.tsx|ts` 의 화면 표시 문자열
- `STAGE = AGENT_RESPONSE` — 에이전트가 사용자에게 내는 응답의 언어/요약 템플릿(언어 지시문, wrap-up 등)
- `STAGE = PROMPT_DOC` — 내부 프롬프트·SKILL.md·문서 (최고 위험, 출력 형식 계약 주의)

---

## 2. 입력 형식

번역 요청 시 아래를 함께 받는다. **문맥 없이는 번역 금지**(로직용인지 표시용인지 판단 불가).

```
파일: <경로:줄>
주변 코드: <해당 문자열이 쓰이는 앞뒤 몇 줄>
대상 문자열:
  [id1] "<원문>"
  [id2] "<원문>"
  ...
```

---

## 3. 절대 규칙 (어기면 기능이 조용히 깨짐)

1. **DNT 우선 판단** — 문자열을 보면 "번역할까?"보다 **"로직에 쓰이나?"를 먼저** 본다. 아래면 **번역 금지**, 출력에서 `KEEP`로 표시:
   - 비교/분기: `==` `===` `switch` `if` `HasPrefix` `strings.Cut` `Contains` `split` 정규식 앵커
   - 저장/직렬화: DB 값, JSON 키, 맵 키, enum 값
   - 백엔드↔프런트 문자열 계약, 에이전트 도구 계약(도구명·파라미터)
   - GLOSSARY **5장(DNT)**·**5.7(값 계약)**·**5.8(쌍)** 에 등록된 것
2. **중국어만 번역, 영어는 원문 유지** — 코드·식별자·명령에 섞인 영어는 그대로.
3. **자리표시자·구조 보존** — `%s %d %v` `{count}` `#%d` 등과 **순서**, `\n`, 마크다운(`**`, 백틱), HTML 태그, JSX 중괄호 표현식.
4. **GLOSSARY 용어 강제** — 표에 있으면 **무조건 그 번역**. 같은 원문은 항상 같은 번역.
5. **코드 불변** — 문자열 리터럴 안의 "언어"만 바꾼다. 식별자·구조·따옴표 종류는 건드리지 않는다.
6. **전각 문장부호 정리** — `，：；、（）` 중국어 문장부호는 한국어 표기로(`, : ; · ()`), UI 라벨 인용 `「」` → 작은따옴표 `'…'`. 단 **5.7의 정규식/파서 안 전각 문자는 보존**.
7. **애매하면 번역하지 말 것** — 확신 없으면 `UNSURE`로 두고 사유를 남긴다. 틀린 번역보다 미번역이 안전하다.
8. **의미 보존** — 조건·제한·경고를 생략하거나 강화하지 않는다. 길이 제한(프롬프트 "120자 이내", `len(reason)>2400`)이 있으면 번역 후 길이를 확인한다.

---

## 4. 단계별 추가 지침

- **UI**: 버튼·메뉴·라벨은 짧고 명확하게(조사 생략 가능), 설명 문장은 존댓말(`~합니다`). 길이 제한(배지/버튼) 주의.
- **AGENT_RESPONSE**: 응답 **언어 지시문**(예: "简洁、准确的中文回答" → "간결하고 정확한 한국어로 답하라")과 사용자향 요약 템플릿만 번역. **도구명·파라미터·enum·출력 형식 마커는 번역 금지.**
- **PROMPT_DOC**: 자연어 설명만 번역. 프롬프트가 요구하는 **출력 형식 계약**(구분자·섹션 마커·JSON 키)은 원문 유지. SKILL.md는 문서가 아니라 **프롬프트로 취급**.

---

## 5. 출력 형식 (반드시 이 형태로)

각 대상 문자열마다 한 블록:

```
[id] STATUS
원문: "<원문>"
번역: "<번역 또는 원문 그대로>"
사유: <KEEP/UNSURE일 때 왜인지 / 적용한 GLOSSARY 용어>
```

- `STATUS` 값: `OK`(번역함) · `KEEP`(DNT라 원문 유지) · `UNSURE`(판단 보류, 사람 확인 필요)
- 치환 코드나 diff를 직접 만들지 말 것. 사람이 검수 후 적용한다.

---

## 6. 끝내기 전 자가 검증

- [ ] 자리표시자(`%s`·`{}`·`#%d`) 개수와 순서가 원문과 같은가
- [ ] 영어 식별자/명령을 건드리지 않았는가
- [ ] GLOSSARY 표의 용어를 그대로 썼는가(같은 원문=같은 번역)
- [ ] 5장/5.7/5.8 항목을 `KEEP` 처리했는가
- [ ] 번역문에 중국어·전각 문장부호가 남지 않았는가(의도적 원문 병기 제외)
- [ ] 조건/제한/경고를 빠뜨리거나 강화하지 않았는가

---

## 7. 예시

**입력**
```
파일: web/src/components/finding-retest-panel.tsx:28
주변 코드: const label = status === 'fixed' ? '已修复' : '复测中'
대상 문자열:
  [a] "已修复"
  [b] "复测中"
```

**출력**
```
[a] OK
원문: "已修复"
번역: "수정 완료"
사유: GLOSSARY 4.1/4.2 — 화면 라벨만 번역, enum `fixed`는 DNT(코드의 'fixed'는 그대로)

[b] OK
원문: "复测中"
번역: "재검증 중"
사유: GLOSSARY 2장 재검증
```

**KEEP 예시**
```
[c] KEEP
원문: "工具 %s 请求审批 (#%d)"
번역: "工具 %s 请求审批 (#%d)"
사유: GLOSSARY 5.7 값 계약 — transcript.tsx 정규식이 이 중국어로 파싱. 번역 시 파싱 깨짐
```
